The Nuru scopeThe workshop scaffold is a small dynamically typed subset. You will work on identifiers, variables, branches, and top-level function declarations and calls. There are no closures. The later reference grows Nuru into a statically typed, bootstrap-ready language.

QUEST 02 · THE STRUCTURAL WEAVER15 minutes

Turn tokens into program structure

The parser records what the program means structurally: declarations live at the top level, statements form blocks, and expressions become nested AST nodes.

Tour, not a TASKNuru uses a handwritten recursive-descent parser. Its expression functions form a precedence ladder—logical OR down through unary and primary—so multiplication nests more tightly than addition. A Pratt parser solves the same operator-precedence problem with parse-function tables and binding powers, but you will inspect that idea rather than implement it here. Keyword recognition already happened in the lexer.

transpiled program · focused excerpt
$ ./nuru-compiler transpile examples/04-compiled.nuru
func fib(n any) any {
	if nuruTruthy(nuruBinary("<=", n, 1)) {
		return n
	}
	return nuruBinary("+", fib(nuruBinary("-", n, 1)), fib(nuruBinary("-", n, 2)))
}

func main() {
	var ans any = fib(10)
	fmt.Println("Fibonacci of 10:", ans)
}

What “compiler” means herenuru-compiler is a source-to-source compiler—a transpiler. It does not define bytecode, a VM, assembly, or an instruction set. Go provides those later layers so this QUEST stays focused on AST-to-code translation.
After the workshop · optional assignments

Keep the QUEST going

These deliberately have no revealed solutions. Use the completed scaffold, then compare your design with the fuller Nuru reference and its roadmap.

Trail 1 · confidence

Differential execution

Run the same .nuru program through the interpreter and transpiled binary, then compare output and failures. Add fuzz cases for lexer/parser boundaries.

Trail 2 · static semantics

Add types and a checker

Evolve var total = 1 toward the reference syntax var total int = 1. Resolve symbols and reject invalid operators before either backend runs.

Trail 3 · useful data

Collections and structs

Add slices, maps, named structs, indexing, and field access. Decide how each value behaves in both the interpreter and generated Go.

Trail 4 · bootstrap readiness

Read and analyse Nuru source

Add args, readFile, and writeFile, then write a Nuru program that tokenises or analyses another .nuru file.

Trail 5 · self-hosting

Write Nuru in Nuru

Port the front end one package at a time, preserve deterministic output, and use the Go seed compiler to compile each generation until Nuru can rebuild itself.

Trail 6 · ecosystem

Choose a roadmap milestone

Prototype modules, a formatter, an LSP, an intermediate representation, or a later LLVM/native backend. Define one small acceptance program before coding.
